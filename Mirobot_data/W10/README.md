# W10 실물 집기 녹화 (L01–L30)

2026-11-04–05에 실물 Mirobot으로 찍은 **집기(pick-up) 시연 녹화**다. 빨강·초록·파랑 블록 세 개를 놓은 배치 30개(L01–L30)에서 색마다 한 번씩 집어 **30배치 × 3색 = 90개**를 찍었다. 정렬 기준을 통과하지 못한 5개는 `trash`로 옮기고 같은 배치·같은 이름으로 다시 찍었다 ([다시 찍은 녹화](#다시-찍은-녹화)).

수집 방법과 명령은 [Mirobot_data/README.md](../README.md), 정렬 기준은 [docs/W10/HDF5_ALIGNMENT.md](../../docs/W10/HDF5_ALIGNMENT.md)에 있다.

## 한눈에

| 항목 | 내용 |
|---|---|
| 작업 | 블록 세 개 중 지정한 색 하나를 집어 들어 올린다. 놓기(place)는 하지 않는다 |
| 조작 | 사람이 키보드로 조작. 한 번에 5 mm 이동, 집게 S40 열림 / S60 닫힘 (1.0초) |
| 시작 자세 | 녹화마다 호밍 없이 같은 초기 자세(X 198.67, Y 0, Z 230.72 mm)에서 시작 |
| 녹화 구간 | F8로 시작하고, 집게를 닫은 뒤 첫 위로(`↑`) 명령에서 3초 뒤 자동 종료. 90개 모두 자동 종료 |
| 녹화 길이 | 11.4–19.9초, 중앙값 15.5초. 시작부터 집게를 닫기까지 중앙값 11.8초 |
| 들어 올린 높이 | 녹화가 끝날 때까지 닫은 높이에서 6–9 cm |
| 카메라 | 손목(팔뚝 브래킷) D405, 640×480·30 fps 요청, 색 보정 `docs/W9/data/calibration/classic_mini.json`. 실제 저장은 초당 약 12장 |
| 블록 | 회전 없이 반듯하게 놓음 (yaw 0) |
| 설정 | 90개 모두 같다 (영상1–10과도 같다) |

## 폴더 이름

- `L<배치>_<색>`: 그 배치에서 그 색을 집은 녹화 (예: `L01_red`)
- 잘못 찍힌 녹화는 `_1`·`_2`로 나누지 않는다. `Mirobot_data/trash/W10/`으로 옮기고 같은 이름으로 다시 찍는다. 그래서 이 폴더에는 배치·색마다 녹화가 하나씩만 있다.

폴더 안 파일 설명은 [Mirobot_data/README.md](../README.md#폴더-안-파일)에 있다.

## 검사 결과 (2026-11-05, 90개 전체)

처음 검사에서는 85개가 통과하고 5개가 정렬 기준을 넘었다. 그 5개를 다시 찍어 검사한 뒤, 지금 이 폴더의 90개는 모두 통과한다.

| 검사 | 결과 (지금 90개) |
|---|---|
| 설정 (카메라·색 보정·집게·초기 자세, 폴더 색 = metadata 색 = reference) | 90개 모두 같음 |
| 종료 | 90개 모두 자동 종료 (`normal`) |
| 파일 | 90개 모두 `frames.jsonl` 항목 수 = PNG 수, PNG 모두 읽힘, `review.mp4` 프레임 수 일치 |
| 집은 위치 | 90개 모두 그 색 블록 위치에서 1.2 cm 이내 |
| 0.05초 정렬 (사진 오차 70 ms 이하, 로봇 기록 간격 150 ms 이하) | **90개 모두 통과** |
| 집기 성공 | 90개 모두 `layout.json`에 `real_success: true`. L21–L30과 다시 찍은 5개는 끝 장면에서 해당 색 블록을 들고 있는 것도 확인 |

90개는 PNG 16,719장, 정렬 timestep 27,820개다. 사진은 초당 9.6–12.4장(중앙값 12.2)으로 저장됐고, 정렬 오차는 최대 66.3 ms다.

## 다시 찍은 녹화

아래 5개는 처음 녹화에서 카메라가 사진을 띄엄띄엄 저장해서, 0.05초 정렬 시각 가운데 70 ms 안에 사진이 없는 순간이 생겼다. 로봇 동작과 집은 위치는 정상이었다. 처음 녹화는 `Mirobot_data/trash/W10/`으로 옮기고, 같은 배치(위 좌표표)에 블록을 놓은 뒤 **같은 이름으로** 다시 찍었다. 이 폴더의 5개는 다시 찍은 녹화다.

| 녹화 | 처음 녹화의 문제 | 저장 속도 | 사진 사이 최대 간격 | 정렬 오차 | 다시 찍은 결과 |
|---|---|---:|---:|---:|---|
| L09_blue | 초당 4장만 저장됨 | 4.0 fps | 320 ms | 146.8 ms | 통과: 12.1 fps, 최대 간격 113 ms, 정렬 53.5 ms |
| L10_blue | 초당 4장만 저장됨 | 4.3 fps | 252 ms | 120.8 ms | 통과: 12.2 fps, 최대 간격 113 ms, 정렬 53.5 ms |

저장 속도, 최대 간격, 정렬 오차는 처음 녹화의 값이다. '다시 찍은 결과'는 11/05 12:16–12:25에 다시 찍은 녹화를 같은 기준으로 검사한 값이다. 다시 찍은 5개 모두 집은 위치가 해당 색 블록에서 0.9 cm 이내였고, 끝 장면에서 블록을 들고 있다.

- **원인**: L09_blue·L10_blue는 11/04 17시쯤 노트북이 배터리로 돌 때 찍혔다. L13·L19는 11/04 저녁 저장 속도가 초당 10장 안팎으로 떨어졌을 때 찍혔다. 기준을 늘리거나 구간을 잘라 통과시키지 않고 다시 찍었다.
- **처음 녹화는 지우지 않았다.** 노트북의 `Mirobot_data/trash/W10/`(git 제외)에 있고, 11/04에 GitHub에 올린 커밋 `15cebae`에도 남아 있다. [HDF5_ALIGNMENT.md](../../docs/W10/HDF5_ALIGNMENT.md)의 미통과 5개가 이 처음 녹화다.
- 카메라 저장 속도는 노트북 전원 상태에 영향을 받는다. 녹화할 때는 충전기를 꽂고 전원 모드를 최고 성능으로 두며, 미리보기 창을 앞에 띄워 둔다.
