# 영상1~10 서버 인수인계

2026-10-29, 로컬 후처리 대상은 `docs/W9/data/raw/영상1`부터 `영상10`까지입니다.

## 로컬에서 완료한 항목

- 사용자가 10개 모두 실물 목표 블록 집기 성공을 확인했습니다. 원본 메타데이터의 `real_success`에 반영했습니다.
- PNG 전체 디코딩, MP4 전체 프레임 디코딩과 PNG 개수 일치, 보정 프로필 로드를 검사했습니다.
- F8~F9 구간을 0.05초 간격으로 정렬했습니다. 각 에피소드에 `aligned.npz`, `alignment_report.json`, `postprocess_report.json`이 있습니다.
- 배열 길이·형상·유한값·쿼터니언 정규화·입력 SHA256을 확인했습니다.
- 보정된 검토용 스냅샷은 이 폴더의 `videoN_review.jpg`, 전체 수치는 `summary.json`에 있습니다.

## 이번 배치의 시간 품질

카메라 설정은 30fps이지만 실제 저장 PNG는 약 10~11fps입니다. 기본 프레임 허용 차이 40ms는 전부 실패했습니다. 이번 배치는 최대 저장 간격 약 139ms의 절반에 해당하는 **70ms를 명시적으로 선택**했습니다. 로봇 상태 공백 기준은 150ms를 유지했습니다. 입력 프레임을 합성하지 않고 가장 가까운 실제 PNG를 사용하므로 동일 PNG가 여러 20Hz 타임스텝에서 사용됩니다.

## 서버에서 받기

서버 프로젝트의 Git 작업 트리가 깨끗한 상태에서 실행합니다. Git LFS가 설치되어 있어야 합니다.

```bash
cd ~/UROP
git pull --ff-only
git lfs pull
```

이미 계산된 결과를 사용하면 됩니다. 서버에서 `prepare`를 옵션 없이 다시 실행하면 기본 40ms 검사에서 실패합니다. 재현이 필요한 경우에만 다음 명령을 실행합니다. 기존 파생 결과는 재생성됩니다.

```bash
cosmos-policy/.venv/bin/python docs/W9/data/postprocess/finish_local.py \
  --max-frame-ms 70 --real-success-reviewed
```

## 서버에서 이어 할 일

로컬 후처리까지 완료했으며 **Panda 추종·HDF5 생성·Cosmos 로더 검사·T5 생성은 아직 실행하지 않았습니다.**

모든 에피소드는 같은 seed 2/reference를 사용합니다. 실물 집기 성공은 확인됐지만 실물 배치와 reference 배치·좌표 매핑의 일치는 별도로 검증하지 않았습니다. 위치를 옮긴 에피소드는 해당 실물 배치와 맞는 reference/매핑이 필요한지 먼저 확인합니다. reference를 수정하면 입력 해시가 바뀌므로 alignment도 다시 계산해야 합니다. `--layout-confirmed`를 일괄로 가정하지 않습니다.

reference와 실물 배치·좌표 매핑의 일치를 확인한 에피소드에 대해 다음을 실행합니다.

```bash
cosmos-policy/.venv/bin/python -m docs.W9.d405.export_hdf5 \
  "docs/W9/data/raw/영상1" \
  --out docs/W9/data/hdf5/mirobot_real \
  --real-success --layout-confirmed
```

다른 에피소드도 번호를 바꿔 반복합니다. 추종 위치 5mm·자세 2° 제한과 마지막 0.5초 시뮬 집기 성공 검사는 기존 기준을 유지합니다. HDF5 생성 후 `docs/W9/MIROBOT_DATA_COLLECTION.md`의 8~9절에 따라 구조·실제 로더·통계·T5를 검사합니다.
