# SO-ARM101 + LeRobot 영상 핵심 정리와 연구 생각

영상: [This $150 Robot Arm Is The Best Way to Start With Advanced Robotics](https://www.youtube.com/watch?v=59JTCvpG_Ec)

기존 정리본을 영상의 큰 목차 흐름에 맞춰 요약하고, 영상 전사와 공식 기술 자료를 대조해 표현을 점검했다. 아래 학습 시간과 성공·실패 사례는 제작자의 실험 결과이다.

## 1. 로봇팔 프로젝트 소개와 목표

SO-ARM101을 이용해 **사람의 시연 데이터를 수집하고, Policy를 학습해 실제 로봇이 물체를 집어 용기에 넣는 작업을 자율적으로 수행하는 과정**을 보여 준다.

사람이 움직이는 Leader Arm과 실제 작업을 수행하는 Follower Arm을 사용한다. 데이터 수집 때는 Follower가 Leader의 움직임을 따라가고, 학습 후에는 Policy가 Follower를 제어한다.

## 2. 프로젝트 진행 계획과 구성 요소

프로젝트는 로봇팔 조립, 소프트웨어 설정, 데이터 수집, Policy 학습, 실제 로봇 평가 순서로 진행된다. Kit에는 두 로봇팔을 구성하는 서보 모터, 케이블, 제어 보드, 3D 프린팅 부품과 고정 부품이 포함된다.

## 3. Vision-Language-Action과 LeRobot

VLA는 카메라 영상과 언어 지시를 바탕으로 로봇의 Action을 출력하는 방식이다. 영상에서는 “티셔츠를 접어라”처럼 직접 프로그램으로 구현하기 어려운 작업을 예로 든다.

실제 로봇과 환경의 상호작용 데이터가 부족하기 때문에 시연 데이터를 수집해 모방학습에 사용하거나, 강화학습과 시뮬레이션 환경을 활용한다. LeRobot은 **데이터 수집·처리와 모델 학습을 연결하는 도구**로 소개된다.

## 4. SO-ARM101 조립, 설정, Calibration

조립할 때는 관절에 맞는 모터 감속비를 확인해야 한다. 서보 ID는 모터를 하나씩 연결해 설정하므로, 조립 과정에서 함께 설정하면 재분리하는 수고를 줄일 수 있다.

LeRobot을 설치한 뒤 Leader와 Follower의 각 관절을 움직여 동작 범위를 Calibration한다. 이후 Leader를 움직여 Follower가 정상적으로 따라가는지 확인한다. 이 단계는 사람이 조작하는 Teleoperation이며, Policy의 자율 작업 수행은 학습 후에 평가한다.

## 5. 운영체제 문제 해결과 실험 환경 구성

Ubuntu 가상 머신에서는 로봇만 제어할 때는 동작했지만, 카메라를 함께 사용하자 영상 끊김과 제어 지연이 발생했다. Ubuntu를 PC에 직접 설치한 Dual Boot 환경에서는 로봇과 카메라가 안정적으로 동작했다.

로봇과 카메라를 고정한 Rig를 만들어 작업 공간을 구성한다. 카메라 영상은 Policy의 Observation이므로, 데이터 수집 전에 로봇 제어와 영상 입력이 동시에 안정적으로 작동해야 한다.

제작자는 기존 VLA를 Zero-shot으로 바로 사용하고 싶었지만, 자신의 Setup에서는 Task별 데이터를 수집해 학습 또는 Fine-tuning해야 했다고 설명한다.

## 6. 데이터 수집, Policy 학습, 자율 실행

### 첫 작업과 데이터 수집

첫 Task는 **빨간 Cube를 집어 검은 Bowl에 넣는 작업**이다. Leader로 시연하면서 Cube와 Bowl의 위치를 바꿔, 다양한 초기 배치의 데이터를 수집한다. 첫 데이터셋은 50 Episodes이며 수집에 약 1시간이 걸렸다.

Recording 화면에서는 카메라 영상과 서보 위치 그래프를 확인하고, 키보드로 다음 Episode 진행이나 재기록을 선택한다. 시연 중 카메라 Observation과 로봇 동작이 Episode 단위로 기록된다.

### 학습 결과와 일반화 실험

약 2시간의 학습 후 로봇은 Cube를 집어 Bowl에 넣는 데 성공했다. Cube 위치나 색상을 바꾼 경우에도 성공했지만, Cube 두 개를 동시에 배치하자 정상적인 작업 수행이 어려웠다. 제작자는 어느 Cube를 선택할지 혼란스러워하는 것처럼 보인다고 해석했다. 새로운 조건에 대한 대응에는 한계가 있었다.

### 복잡한 작업의 실패와 재학습

여러 Lego Brick을 정리하는 작업에서는 ACT와 SmolVLA를 시도했지만 안정적인 수행이 어려웠다. 작업을 **큰 Brick 하나를 회색 Bin에 넣기**로 단순화하고, 다시 50 Episodes를 수집했다. 이후 30,000 Steps를 약 4시간 학습해 작업 성공을 확인했지만, 반복 실행에서는 실패도 발생했다.

### ACT와 SmolVLA의 관찰 결과

ACT 실험에서는 Brick을 집은 뒤 Bin을 옮겨도 기존 위치에 놓는 경우가 있었다. 제작자는 이를 여러 단계의 동작을 미리 예측하는 방식과 연결해 설명했다. 마지막 SmolVLA 실험에서는 이동한 Bin을 따라가 Brick을 넣는 모습을 보였다. 이 결과는 해당 실험에서의 관찰이며, 안정성과 환경 변화 대응은 추가 평가가 필요하다.

전체 과정은 **Task 설계 → 시연 데이터 수집 → 학습 → 실제 실행 → 실패 확인 → Task·데이터 수정 → 재학습**으로 이어진다.

## 7. STS3215 Servo Motor

STS3215는 현재 위치를 읽을 수 있는 서보 모터이며, 이 기능이 Leader의 관절 위치를 Follower에 전달하는 제어에 사용된다. 모터를 Daisy Chain으로 연결하고, 제어 보드를 통해 컴퓨터나 마이크로컨트롤러에서 통신할 수 있다. 같은 계열에서도 감속비와 Torque가 다른 버전이 있으므로 관절에 맞는 모터를 선택해야 한다.

## 내가 느낀 점과 앞으로 생각해야 할 점

### 1. VLA의 목적과 데이터 확보 방식

전통적인 로봇 제어 방식으로 “티셔츠를 접어라” 같은 복잡한 작업을 프로그램으로 작성하기는 어렵다. VLA는 영상과 언어 지시를 바탕으로 Action을 생성해 이런 작업에 접근할 수 있게 한다.

Real world에는 로봇의 상호작용 데이터가 충분하지 않다. 영상에서는 사람이 로봇을 직접 조작해 시연 데이터를 수집하고, 그 데이터를 이용해 로봇의 행동을 학습한다. 여기서 **사람의 시연은 학습 데이터의 원천이고, 모방학습은 그 시연을 따라 행동하도록 Policy를 학습하는 과정**이다. 강화학습과 Simulation도 언급되지만, 영상의 실제 실험은 시연 데이터를 이용한 학습을 중심으로 진행된다.

우리 실험에서는 **시뮬레이터와 사람의 시연을 함께 사용한다.** 모방학습은 학습 방법이고, 시뮬레이터는 시연 수집과 Policy 평가 등에 사용할 수 있는 환경이다. 사람이 시뮬레이터 안의 로봇을 조작해 시연 데이터를 만들고, 그 데이터로 모방학습을 진행할 수도 있다. 실제로 LIBERO는 사람의 Teleoperation 시연 데이터와 모방학습 실험을 제공한다. [LIBERO 공식 자료](https://github.com/Lifelong-Robot-Learning/LIBERO)

**생각해 볼 질문:** 우리 실험에서 사람의 시연을 어디에서 어떻게 수집하고 모방학습에 사용할까? 이 과정에서 시뮬레이터는 어떤 역할을 할까? 시뮬레이터에서 수집한 시연과 실제 로봇에서 수집한 시연의 차이, 반복 평가의 이점, 실제 로봇에 적용할 때 발생하는 차이를 살펴보고 두 환경의 데이터를 어떻게 연결할지 정리해야 한다.

LeRobot 프로젝트의 목적은 데이터 수집, 처리, 다양한 모델 학습을 연결하는 것이다. 우리 연구에서도 이 전체 흐름을 이해하고 재현하는 것이 중요하다.

### 2. Leader Arm의 역할을 MiRobot에서 어떻게 구현할까?

SO-ARM101은 Leader Arm과 Follower Arm 두 대를 사용한다. 사람이 Leader를 움직여 Follower의 동작을 시연하고, 기록된 데이터를 모방학습에 사용한다.

MiRobot에서는 사람이 Controller로 목표 위치·자세를 입력하고, Inverse Kinematics와 로봇 제어 코드를 통해 움직이는 방식으로 Leader Arm의 조작 역할을 대신할 수 있을 것 같다. Inverse Kinematics는 목표 위치·자세에 맞는 관절값을 계산하며, 사람의 입력과 명령 전달 기능도 함께 필요하다. 기존 코드가 조작에 따라 MiRobot을 움직이는 것은 3D 구조물을 장착한 실험 영상에서 확인했다.

다음에는 이 조작 방식을 이용해 Task를 반복 시연하고, 학습에 사용할 Observation과 Action을 함께 기록할 수 있는지 확인해야 한다.

### 3. 실행 환경과 OASYS 서버 활용

영상에서는 Ubuntu 가상 머신과 Conda 환경을 사용하다가 카메라·USB 문제로 Dual Boot로 전환했다. 이후 Windows와 Ubuntu 사이의 시간 설정 등에서도 문제가 발생했다.

우리는 OASYS 서버의 Conda 환경에서 학습과 모델 실행을 진행하려고 한다. 프로젝트 문서에는 주 정책으로 **Cosmos Policy(Cosmos-Predict2-2B 기반)**가 정리되어 있으며, LIBERO용 체크포인트는 `nvidia/Cosmos-Policy-LIBERO-Predict2-2B`이다. 로컬 운영체제와 관계없이 SSH로 서버에 접속할 수 있다는 점에서 편리할 것 같다. [Cosmos Policy 공식 코드](https://github.com/NVlabs/cosmos-policy)

다만 서버에서 모델이 실행되는 것과 실제 로봇까지 연결된 전체 과정이 동작하는 것은 별도로 확인해야 한다. 특히 로컬에 연결된 MiRobot과 카메라의 데이터를 서버로 전달하고, 서버의 Action 출력을 로봇에 적용하는 흐름과 지연을 검토해야 한다. 서버 접속을 위한 SSH 연결과 실시간 로봇 제어를 위한 데이터 통신 방식도 구분해서 설계해야 한다.

### 4. 로봇과 카메라의 배치

영상에서는 나무판을 작업 공간으로 사용해 Follower를 고정하고, Leader는 책상에서 Controller 역할로 사용한다. 화면을 보고 Leader가 고정되지 않았다고 생각했지만, 전사에서 제작자는 Leader를 책상에 고정했다고 설명한다.

내가 확인한 장면에서는 외부 카메라 한 대가 보이며, 로봇팔과 작업 공간을 촬영하는 방식으로 보인다. 다만 영상 전체의 카메라 수와 구성은 이 관찰만으로 확정하지 않는다. 우리 실험에서도 로봇, Object, Target을 안정적으로 관찰할 수 있도록 카메라 위치와 촬영 범위를 정해야 한다.

### 5. Zero-shot과 Task별 학습의 관계

영상에서 제작자는 기존 모델로 자신의 환경에서 Zero-shot 작업을 수행하고 싶었지만, Task별 데이터 수집과 Fine-tuning이 필요했다고 설명한다. 이 설명만으로 모든 Zero-shot 실행이 불가능하다고 단정할 수는 없지만, 우리 환경에 맞는 데이터 수집과 학습의 필요성을 생각하게 한다.

Cosmos Policy는 사전학습된 영상 모델인 Cosmos-Predict2를 로봇 시연 데이터로 추가 학습해 Action을 생성하도록 만든 정책이다. 프로젝트에서 사용하는 LIBERO용 체크포인트는 LIBERO의 Observation과 Action 형식에 맞춰 학습되어 있다. 이를 MiRobot에 적용하려면 카메라 입력, 로봇 상태, Action의 의미·단위·좌표계와 정규화를 맞추고, MiRobot 데이터로 추가 학습할 필요가 있는지 검토해야 한다. 사전학습되어 있다는 사실만으로 새로운 로봇에서 Zero-shot 수행이 보장되지는 않는다. [Cosmos Policy 연구 설명](https://research.nvidia.com/labs/cosmos-lab/cosmos-policy/), [공식 입력·출력 예시](https://github.com/NVlabs/cosmos-policy)

교수님이 지난번에 제시한 Zero-shot 관련 내용은 이번 프로젝트에서 기본 흐름을 완성한 뒤, 추가로 확장해 연구할 주제로 생각하고 있다.

### 6. 실제 Task 시연과 학습 데이터 구성

영상의 첫 Task는 빨간 블록을 검은 그릇에 넣는 것이다. Leader Arm으로 시연하면서 블록과 그릇의 위치를 바꿔 데이터를 수집한다. 목표는 학습 때와 다른 위치에서도 블록을 집어 그릇에 넣는 것이다.

우리는 Leader Arm 대신 Controller 코드를 사용해 같은 방식으로 시연할 수 있을 것 같다. 기존 Inverse Kinematics 코드가 실제 MiRobot을 조작대로 움직이므로, 이를 데이터 수집 단계로 연결하는 방법을 생각해야 한다.

**추가로 알아볼 내용:** 수집한 영상과 로봇 상태·Action을 어떻게 모델이 학습할 수 있는 데이터로 구성할까? 각 시점의 카메라 영상·로봇 상태와 사람이 내린 Action을 시간에 맞춰 기록하고, 그리퍼 동작과 Episode 구분도 포함해야 한다. 현재 측정한 관절 상태와 로봇에 보낸 목표 명령을 구분해 어떤 값을 Observation과 Action에 사용할지 정해야 한다. [LeRobot 시연 수집·학습 가이드](https://huggingface.co/docs/lerobot/il_robots)

### 7. 데이터 다양성과 새로운 상황에 대한 대응

영상에서는 빨간 블록을 넣는 Task를 학습한 뒤 색상이 다른 블록 하나에도 대응했지만, 블록 두 개를 동시에 놓자 작업이 정상적으로 수행되지 않았다. Object 수처럼 학습 때와 다른 변수가 생기면 성능이 떨어질 수 있다는 점을 보여 준다.

우리 실험에서도 여러 초기 배치와 상황을 포함한 데이터를 구성하고, 학습한 Policy가 변화에 얼마나 대응하는지 확인해야 한다. 기존 프로젝트 계획에서 주 정책은 Cosmos Policy이고 ACT는 데이터 품질 검증 등을 위한 진단용이므로, 영상의 ACT 실험을 우리 연구의 주 모델과 구분해서 참고해야 한다. 어떤 변화를 데이터에 포함하고 어떤 변화를 평가에 사용할지도 생각해야 한다.

### 8. Episode 기록과 로봇 상태 시각화

영상의 데이터 수집 화면에서는 카메라 영상과 서보 위치 그래프를 함께 확인하고, 한 Episode가 끝나면 좌우 화살표 키로 다음 기록이나 재기록을 선택한다.

MiRobot에서도 말단의 위치와 자세인 `x, y, z, rx, ry, rz`를 그래프로 표시할 수 있지 않을까? 로봇 관절 위치인 `qpos`와 말단의 위치·자세는 서로 다른 값이다. 명령한 목표값과 실제 측정값도 구분하고, 위치·각도의 단위와 좌표계를 정해 어떤 값을 기록하고 시각화할지 다음 Action Plan에서 알아봐야 한다.

### 9. Action Policy가 예측하는 동작 범위

영상에서 ACT는 여러 단계의 Action Sequence를 예측하는 것으로 설명된다. 공식 자료를 보면 **ACT와 SmolVLA 모두 여러 단계의 Action Chunk를 출력한다.** 따라서 영상에서 나타난 반응 차이를 ACT만 여러 단계를 예측하기 때문이라고 설명해서는 안 된다. 예측한 Action 중 몇 단계를 실행한 뒤 새로운 Observation으로 다시 예측하는지, 실행 주기와 데이터 구성은 어떤지 함께 확인해야 한다. [ACT 공식 설명](https://huggingface.co/docs/lerobot/act), [SmolVLA 공식 설명](https://huggingface.co/docs/lerobot/smolvla)

우리 모델에서도 한 번에 몇 단계의 Action을 예측하는지, 새로운 Observation을 언제 반영하는지 확인해야 한다. 이를 실제 실행 중 환경 변화에 대응하는 능력과 연결해 생각해 볼 수 있다.
