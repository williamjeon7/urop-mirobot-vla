### 5-1-1. 프레임 회전 `F` 를 수치로 — 실물 없이 된다

**지금 `F` 의 근거는 둘 다 눈이다** (9/17 기울는 방향·그리퍼 조 방향, 9/21 두 영상 나란히).
`F` 는 이산적 선택이라 눈으로 충분하긴 하지만, "수치로 확인했나" 에는 **아니오** 가 정확한 답이다.

**기존 오차 숫자는 `F` 에 눈을 감고 있다.** 둘 다 자기 기준 대비라서다 —
Mirobot 0.306mm 는 *우리가 적어 준 G-code* 대비, Panda 1.95mm 는 *`F` 로 변환한 목표* 대비다.
`F` 가 90° 틀려도 두 숫자는 똑같이 나온다. 왕복 상쇄와 같은 구조다.

### 5-2. 누적인지 아닌지 — 먼저 구조를 본다

**구조상으로는 누적되지 않아야 한다.** 양쪽 모두 **절대 목표를 매번 새로 잡기** 때문이다.

| | 왜 안 쌓이나 |
|---|---|
| Mirobot | `G90`·`M20` **절대 좌표**. 직전 오차가 다음 목표에 들어가지 않는다 ([CONTROL.md](../W3/CONTROL.md) 1절) |
| Panda 추종 루프 | 목표를 **고정**하고 매 스텝 `(목표 − 현재)` 를 다시 계산한다 — closed-loop. 도착을 확인하고 다음 waypoint 로 간다 |

**waypoint 마다 오차가 독립일 것으로 예상한다. 그러나 아직 재지 않았다** — 이 예상이 맞는지 보는 것이 ④ 의 답이다.

- [ ] **누적이 생길 수 있는 자리**를 따로 본다

  - **Mirobot 스텝 손실** — 막히면 모터가 스텝을 잃는다. 이건 **진짜 누적**이고, `?` 보고값으로는 안 보일 수 있다
  - **보고 `Z` 상수 오프셋** — 상수라면 누적이 아니다. **정말 상수인지**를 긴 궤적에서 확인한다

**`--auto` 없이** 줄마다 Enter 로 간다 — absolute 파일은 처음이라 **1회차(`r1f`·`r1b`, 13줄)는 한 줄씩 보고**,

```

열기·닫기를 3번씩 하며 **자로 개폐 폭**과 **다 열리고 닫히는 데 걸리는 시간**(눈대중)을 적는다.
`$$` 에 관절 한계로 보이는 값이 있으면 그대로 옮겨 적는다. **J5 를 한계까지 직접 몰아가지는 않는다.**

**④ (여유 있으면) A 를 `--stream` 으로 한 번 + 휴대폰 촬영** — W3 에 남은 촬영 겸 실제 기록 주기 확인

```

`--stream` 은 보낸 줄이 취소되지 않는다 — 중간에 `Ctrl-C` 를 눌러도 버퍼에 들어간 이동은 끝까지 간다.

**멈춰야 할 때**

| 상황 | 할 일 |
|---|---|
| 줄이 거부됨 (`error`), 알람 | 기본 모드면 `q`, `--auto` 면 `Ctrl-C` — 다음 줄을 안 보낸다. 화면의 원문을 그대로 적어 둔다 |
| 테이블·케이블·마운트에 닿을 것 같음 | **전원·리셋으로 즉시 정지.** 어느 라벨에서였는지 적는다 |
| 예상과 다른 방향으로 크게 움직임 | 멈추고 라벨을 적는다 — 파일이 아니라 로봇 상태(호밍 안 됨 등)가 원인일 수 있다 |
