# 명령을 주면 무슨 일이 일어나나 — Panda(LIBERO) vs Mirobot

> **참조** · 확인 2026-09-20 · 기준 robosuite 1.4.0 소스, 9/17 LIBERO 측정과 Mirobot 실물
> 두 로봇이 명령을 어떻게 받아 움직이는지. 측정값은 [LIBERO_AXES.md](LIBERO_AXES.md), 작업은 [CHECKLIST.md](CHECKLIST.md).

둘 다 "손을 어디에 둘지" 를 받는다(Cartesian). 다른 것은 **그 목표까지 어떻게 가느냐**다.

## 1. 한 스텝에 일어나는 일

```
Panda (LIBERO)
  받는 것    [Δx Δy Δz Δrx Δry Δrz gripper]    변화량. 1.0 = 0.05m / 0.5rad
     ▼
  목표       목표 = 현재 + 변화량               control_utils.py:135, 177
     ▼
  힘         150 × (목표 − 현재) − 24.5 × 속도   가상의 스프링 + 댐퍼, osc.py:158,319
     ▼
  관절 토크  그 힘을 내는 토크 + 중력 보상       osc.py:345
     ▼
  물리       0.05초 진행 → 목표의 약 25% 만 간다

Mirobot
  받는 것    G0 X Y Z A B C                     절대 좌표 (G90 · M20)
     ▼
  IK         그 자세를 만드는 관절 각도          펌웨어
     ▼
  스텝 모터  그 각도까지 회전 → 도착해서 멈춘다
```

## 2. 비교

| | Panda (LIBERO) | Mirobot |
|---|---|---|
| 명령 형식 | **변화량** (현재 기준) — `"control_delta": true` | **절대 좌표** (`G90`·`M20`) |
| 명령 단위 | 단위 없는 `[-1, 1]`, 컨트롤러가 m·rad 로 | mm 와 도 |
| 내부 처리 | 목표와의 차이 → **힘** → 관절 토크 | **IK** → 관절 각도 → 스텝 모터 |
| 한 스텝 뒤 | 목표의 **약 25%** (위치 26%, 회전 23~25%) | **도착**해서 멈춘다 |
| 도착 확인 | 관측을 다시 읽어 오차를 본다 | `?` 로 `Idle` 인지 본다 |
| 막히면 | 힘이 걸린 채 멈춘다 (밀고 있다) | 모터가 계속 돌려다 스텝을 잃을 수 있다 |
| **위치를 어디로 보고하나** | **파지점** — 손가락 사이 (`eef_pos` = `grip_site`). 플랜지에서 공구 축으로 97mm | **플랜지** — 홈 좌표가 링크 길이 합과 맞는다 (`../W2/CHECKLIST.md` 4절) |
| 회전 중심 | **파지점**(`grip_site`) — 손끝이 제자리 | **플랜지** — Cartesian `G0` 로 자세만 바꿀 때 (9/17 실측) |
| 명령하지 않은 축 | 10% 이하로 따라 움직인다 | 자세만 바꾸면 위치 0.07mm 이내 유지 (9/17) |

**플랜지** 는 팔 끝에서 공구를 붙이는 면이고, **파지점** 은 그리퍼 손가락 사이의 무는 점이다. 두 로봇이 서로 다른 점의
좌표를 말하므로, 우리 변환은 **플랜지 ↔ 플랜지** 로 맞춘다 (`common/workspace.py`). Panda 롤아웃에서 `eef_pos`(파지점) 외에
`flange_pos`(`robot0_right_hand`) 를 따로 기록하는 이유다.

측정값과 근거는 [LIBERO_AXES.md](LIBERO_AXES.md) 2·3절, Mirobot 쪽은 [CHECKLIST.md](CHECKLIST.md) 8절, ③ "LIBERO eef 위치의 기준점".

### 2-1. 손끝 보정이 왜 필요한가

플랜지 자세를 양쪽이 똑같이 맞춰도 손끝은 어긋난다. 각 로봇의 손끝은 자기 플랜지에서 공구 축으로 `L` 만큼 떨어져 있다.

```
손끝 = 플랜지 + R · (0, 0, L)              L = 그 로봇의 플랜지 → 파지점 길이
어긋남 = R · (0, 0, 1) · (L_panda − L_mirobot) = R · (0,0,1) · ΔL
```

크기는 **`ΔL` 로 일정**하고 방향만 공구 축을 따라 돈다. 그래서 top-down 에서는 **높이 차**로만 보이고,
`θ` 만큼 기울일수록 **수평 성분 `ΔL · sin θ`** 가 자란다. `L_panda` = 97mm, `L_mirobot` 은 미측정이다 (8절).

**무엇끼리 맞추면 무엇이 맞나**

| 맞추는 점 | 플랜지 경로 | 손끝 경로 | 필요한 값 | 지금 |
|---|---|---|---|---|
| **플랜지 ↔ 플랜지** | **정확히 같다** | `ΔL` 만큼 어긋난다 | 없음 | **이걸 쓰는 중** — 9/20 왕복 0.30mm |
| **파지점 ↔ 파지점** | 어긋난다 | **정확히 같다** | Mirobot `L` | 못 함 — `L` 미측정 |

지금 플랜지끼리 맞추는 것은 선택이 아니라 **`L` 이 없어서**다. Mirobot 은 플랜지만 보고하므로 `L` 없이는
손끝 좌표를 계산할 수 없다. 재고 나면 어느 쪽으로 맞출지 고를 수 있게 된다.

**손끝을 맞춰야 하는 이유**

| | |
|---|---|
| **LIBERO proprio 가 손끝이다** | `eef_pos` = `grip_site` = 파지점. 이 프로젝트가 하려는 것이 **proprio 를 바꿔 끼우는 것**인데, 바꿔 낄 그 숫자가 손끝 좌표다. 손끝이 안 맞으면 바꿔 끼운 숫자의 의미가 달라진다 |
| **과제가 손끝으로 정의된다** | 무는 곳·놓는 곳이 손끝이다. 플랜지가 맞아도 손끝이 벗어나면 물지 못한다 |
| **top-down 만 보면 안 드러난다** | 수평 어긋남이 `ΔL · sin θ` 라 기울이지 않으면 0 이다. **회전이 든 궤적에서만** 보인다 — 이번 주 궤적에 회전을 넣은 이유와 같다 |

**맞바꿈** — 손목 카메라는 플랜지에 매달리므로, 그림을 맞추는 데는 플랜지끼리 맞추는 쪽이 유리하다
(두 로봇의 카메라 장착 오프셋이 달라서 그것만으로 같아지지는 않는다). 어느 쪽을 맞출지는 `L` 을 재고 정한다.

**9/20 실물에서 드러난 모습** — 구간 3 에서 `y` 명령이 없는데 팔이 오른쪽으로 27.0mm 되돌아왔다.
Panda 가 파지점을 중심으로 16.59° 돌 때 플랜지가 `97 × sin16.59° = 27.7mm` 휘는데, 우리가 그 플랜지 경로를
그대로 옮겼기 때문이다. **틀린 것이 아니라 충실한 것**이지만, 우리가 옮긴 점이 과제와 상관없는 점이라는 뜻이다
([CHECKLIST.md](CHECKLIST.md) 5-2).

## 3. Panda 를 목표 자세까지 가게 하려면

액션은 변화량이라 "여기로 가라" 가 없다. 세 가지를 시뮬에서 재 봤다 — 액션 `0.5`(목표 오프셋 25mm)로 x 방향, 9/20.

| 방식 | 2스텝 | 10스텝 | 20스텝 | 40스텝 |
|---|---|---|---|---|
| **① 한 번 주고 기다리기** | 4.3mm | 5.8mm | — | **5.9mm 에서 선다** |
| **② 같은 값을 계속 주기** | 6.7mm | 50.9mm | 115.1mm | 240.2mm (계속 간다) |
| **③ 목표를 고정하고 매 스텝 `(목표 − 현재)/0.05` 로 다시 계산** | 2.4mm | **25.6mm** | 25.8mm | 25.0mm |

- **①이 25mm 에 못 가는 이유** — 목표는 매 스텝 `현재 + 액션` 으로 다시 계산된다. 액션을 0 으로 주는 순간
  **목표가 "지금 이 자리"** 가 되어 당기는 힘이 사라진다. 25mm 라는 목표는 액션을 준 그 한 스텝에만 있었다
- **②는 도달이라는 개념이 없다.** 목표가 매 스텝 앞으로 다시 놓여 당근을 쫓듯 계속 간다. 멈추려면 액션을 0 으로 줘야 한다
- **③이 우리가 쓸 방식이다.** 9스텝 만에 1mm 안에 들고, 최대 2mm 넘었다가 선다. 액션이 `0.50 → 0.22 → 0.01` 로 저절로 줄어든다.
  여러 축이 섞이면 **방향을 유지한 채** 크기만 줄여야 한다 — robosuite 는 성분마다 `[-1, 1]` 로 자르므로 (`base_controller.py:120`)

### 남들은 어떻게 하나

| 목적 | 방식 |
|---|---|
| 데모 수집 (LIBERO) | 사람이 **SpaceMouse 로 20Hz 텔레오퍼레이션** — 사람이 루프 안에 있다 |
| 정책 평가 | 정책이 관측을 보고 델타를 내면 그대로 `env.step`. 도착 판정 없음 |
| 정해진 자세열 재생 (MimicGen) | **절대 목표를 추적하며 20Hz 로 델타 액션으로 바꾸는 컨트롤러** — ③과 같다. 구간 시작에 보간을 덧붙인다 |

robosuite 에는 `controllers/interpolators/linear_interpolator.py` 와 절대 모드(`control_delta: false`)도 있지만,
LIBERO 설정은 `"interpolation": null` 이고 절대 모드는 문제 보고가 있다 (robosuite 이슈 #139·#562).

→ **③(절대 목표 → 매 스텝 델타)은 표준이다.** 다만 남들은 정해진 시간에 다음 목표로 넘어가고,
우리는 **도착을 확인한 뒤** 넘어간다 — 이번 주가 시간을 보지 않기 때문이다 ([CHECKLIST.md](CHECKLIST.md) 0절).

## 4. 우리 작업에 주는 영향

| 방향 | 영향 |
|---|---|
| **LIBERO → Mirobot** (5-2) | **없다.** 명령이 아니라 Panda 가 *실제로 있었던* 자세를 기록해 절대 좌표로 보낸다 |
| **Mirobot → LIBERO** (5-1) | **있다.** Panda 는 목표에 한 번에 닿지 않으므로, 매 스텝 현재를 다시 읽어 목표를 다시 거는 closed-loop 로 간다 |
| 정책을 Mirobot 에 연결 (범위 밖) | **문제가 된다.** 정책은 Panda 컨트롤러 특성이 섞인 변화량을 낸다. 그대로 Mirobot 에 주면 한 스텝에 약 4배 크게 움직인다 → [CHECKLIST.md](CHECKLIST.md) 10절 미팅 질문 |

## 5. 왜 이렇게 다른가

- **Panda 는 사람과 같이 쓰는 로봇**이라, 부딪혔을 때 힘이 제한되도록 임피던스 제어를 쓴다. 목표를 스프링으로 당기는 방식이라
  경로가 부드럽고, 막히면 밀면서 멈춘다. LIBERO 데모와 Cosmos Policy 의 액션에는 이 특성이 이미 섞여 있다
- **Mirobot 은 교육용 스텝 모터 팔**이라, 정해진 각도로 가는 위치 제어다. 힘을 느끼지 못하고 되먹임도 없다.
  대신 목표에 정확히 서고, 같은 명령이면 같은 자리에 선다
