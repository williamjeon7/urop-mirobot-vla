# 주차별 실행 가이드 (W1 ~ W14)

> 매주 월요일에 해당 주차를 열고 5일 계획을 세우는 용도
> 전체 설계 근거는 `UROP_프로젝트_계획.md` 참조

## 사용법

각 주차 구조:
- **주간 목표** — 한 문장
- **주말에 있어야 할 것** — 산출물. 이게 없으면 다음 주로 못 넘어감
- **A / B 작업** — A=로봇 앞에 물리적으로 있어야 하는 일, B=서버에서 하는 일.
  사람에 고정하지 말고 주차별 부하에 맞춰 조정 (W1~W5는 A 편중, W8·W11~W13은 B 편중)
- **확인 체크리스트** — 실제로 손으로 확인할 항목
- **게이트** — 통과/미달 판정
- **흔한 함정** — 이 주차에서 시간을 날리는 패턴

---

## 우선순위 규칙 (상시)

> **최소 목표가 흔들리면 권장 목표 작업을 즉시 중단한다.**

| 신호 | 조치 |
|---|---|
| W5 재생 검증 80% 미달 | 권장 목표 작업 전면 중단, 데이터 파이프라인 수정 집중 |
| W7 ACT 성공률 30% 미만 | 실패 데이터셋 구축 중단, 데이터 품질 원인 규명 우선 |
| W8 Cosmos 학습 미수렴 | 신호 A 작업 보류, **Phi 백업으로 전환 판단** |
| W9 언어 준수율 60% 미달 | 권장 목표 전면 포기, W10~W14 전량 최소 목표 투입 |

# W1 — 로봇 개봉 및 기동

**주간 목표**: 박스 안의 로봇을 Python SDK로 움직일 수 있는 상태로 만든다.

**주말에 있어야 할 것**
- SDK 스크립트로 관절을 명령대로 움직인 로그
- 그리퍼 개폐 동작 확인
- 작업대에 고정된 로봇 + 정리된 케이블
- 서버 Docker 환경 + cosmos-policy 설치 완료

### A 작업

**개봉 및 확인**
- [ ] 부품 목록 대조 (매뉴얼 1.2절 표준 세트 10종)
- [ ] **그리퍼 종류 확인** — 마이크로 서보 / 공압 세트(석션컵·2지·볼)
- [ ] 공압이면: 컴프레서 소음, 튜빙 경로, 전원 추가 확인
- [ ] 부품 누락 시 **즉시 문의** (배송 대기가 W1을 잠식)
- [ ] 매뉴얼 2장(Safety) + 부록 III(트러블슈팅) **두 사람 모두 읽기**

**조립 및 드라이버**
- [ ] 로봇 조립, 익스텐더 박스 IDC 케이블 연결
- [ ] **전원 끈 상태에서** 그리퍼 장착
- [ ] 그리퍼 커넥터 고정 돌기 제거 후 GRIPPER 소켓 삽입
- [ ] CH340 드라이버 설치 → 장치 관리자에서 `USB-SERIAL CH340 (COMx)` 확인

**통신 및 기동**
- [ ] WLKATA Studio 설치 (**경로 영문만**, D:\ 또는 E:\ 루트)
- [ ] Studio 연결 확인 (좌상단 CONNECTED, 115200)
- [ ] 펌웨어 버전 확인 → 필요 시 업데이트 (Studio v1.014 이상)
- [ ] **HOMING 실행**
- [ ] 호밍 실패 시 → 부록 III "1축 센서 불량" 절차
      (나사 조임 → `$20=0 $21=0` → `M50` → J1 정렬 → HOMING → `$20=1 $21=1`)
- [ ] 필요 시 캘리브레이션 (`M50` → Setting > Calibration > Start → J1~J6 정렬 → Finish → HOMING)
- [ ] 비상정지 절차 1회 실습: Studio STOP → 베이스 RESET → HOMING

**SDK 및 셋업**
- [ ] `pip install wlkata-mirobot-python`
- [ ] `home()` → `set_tool_pose()` → `arm.pose` 읽기 성공
- [ ] 관절각 개별 명령·읽기, 그리퍼 SDK 제어
- [ ] **그리퍼 개구 폭 실측 (mm)** → 25mm 큐브가 들어가는지
- [ ] 로봇을 작업대에 **볼트 고정**, 케이블 정리

**작업 공간 탐색**
- [ ] Studio TEACHING으로 블록·그릇 예상 위치 도달 확인
- [ ] 315mm 반경 내 유효 작업 영역 스케치, 도달 불가 영역 기록

### B 작업
- [ ] 서버 접속, CUDA/드라이버 버전 확인
- [ ] **GPU 공유 방식 확인** — 스케줄러 유무, 점유 표시 관례, 잡 강제종료 가능 여부
- [ ] 우리 몫 카드 번호 확정 및 연구실 공지
- [ ] **W3에 4장을 몇 시간 확보 가능한지 문의** (풀 파인튜닝 실증용)
- [ ] **Docker 환경 구축** (cosmos-policy는 Docker 기반, SETUP.md 참조)
- [ ] cosmos-policy 저장소 클론, 의존성 설치
- [ ] LIBERO 시뮬 환경 설치
- [ ] `Cosmos-Policy-LIBERO-Predict2-2B` 다운로드 → **추론 1회 실행 확인**
- [ ] Phi-3.5-vision 체크포인트 다운로드

### 게이트
| 판정 | 기준 |
|---|---|
| **통과** | SDK로 관절 제어 + 그리퍼 개폐 성공, Cosmos 추론 1회 성공 |
| 미달 | 드라이버/펌웨어/1축 센서/Docker 중 원인 특정, 지연 기록 |

### 흔한 함정
- CH340이 최신 Windows에서 안 잡힘 → 서명 문제, 구버전 시도
- Studio 압축 해제 경로에 한글 → 실행 실패
- 호밍 실패를 소프트웨어 문제로 오해 → **1축 센서 하드웨어 이슈부터 확인**
- 그리퍼를 전원 켠 채 꽂아 회로 손상
- Docker 이미지 빌드가 예상보다 오래 걸림 (저장소가 신규라 문서가 얇음)
- **J1/J3를 손으로 돌려보다 파손 — 절대 금지**

# W2 — 제어 스택 및 실측

**주간 목표**: 제어 루프의 물리적 한계를 숫자로 확정한다. 이 숫자가 이후 설계를 결정한다.

**주말에 있어야 할 것**
- 지연·주파수 측정 결과표
- 카메라 2대 동시 30fps 캡처 스크립트
- EE 명령 시 관절각 로그 (액션 표현 판정 근거)
- 네트워크 왕복 시간

### A 작업

**제어 래퍼**
- [ ] 관절각 명령 / 실측 읽기 함수
- [ ] EE pose 명령 / 읽기 함수
- [ ] 그리퍼 개폐, 호밍·리셋·복구 함수
- [ ] 관절 범위 밖 명령 클리핑
- [ ] 비상정지 → RESET → HOMING 복구를 코드로 내장

**지연 실측 (이번 주 핵심)**
- [ ] **명령 전송 → 실제 도달 시간** (이동 거리별)
- [ ] **상태 읽기 최대 주파수**
- [ ] 연속 명령 스트리밍 시 버퍼 동작
- [ ] → **10Hz 가능한가? 불가하면 5Hz로 하향 결정**

**액션 표현 판정용 데이터**
- [ ] EE 좌표로 직선 궤적 명령하며 관절각 전 구간 로깅

- [ ] **J5 범위(-180°~+40°)에서 top-down 자세 가능한지 확인**
- [ ] 예상 배치 영역 전체에서 IK 해 존재 확인

**카메라**
- [ ] 고정 카메라 마운트 (씬 전체 + 그릇 포함)
- [ ] 손목 카메라 마운트 — **케이블 간섭·당김 확인**
- [ ] **USB 대역폭**: 2대 동시 30fps 10분 연속 → 프레임 드롭 여부
- [ ] 드롭 시 다른 USB 컨트롤러/허브로 분산
- [ ] 타임스탬프 정렬 확인 (지연이 일정하면 OK)
- [ ] **조명 고정** (자연광 금지, 인공 조명 권장)

### B 작업
- [ ] policy server / client 골격
- [ ] **로봇 PC ↔ 서버 왕복 시간 측정**
- [ ] 왕복이 수백 ms면 청크 실행 길이 증가로 설계 반영
- [ ] cosmos-policy 코드 구조 파악 — 데이터 config, 임베디먼트 정의 위치 확인

### 측정 결과 기록
- [ ] 제어 주파수: ___ Hz
- [ ] 상태 읽기 주파수: ___ Hz
- [ ] 네트워크 왕복: ___ ms
- [ ] EE 명령 시 관절각 불연속: 있음 / 없음
- [ ] 카메라 2대 30fps 10분 무드롭: 통과 / 실패

### 게이트
| 판정 | 조치 |
|---|---|
| 10Hz 확보 | 계획대로 |
| 5~10Hz | 제어 주파수 하향, 청크 길이 조정 |
| 5Hz 미만 | 태스크를 준정적으로 재설계 |

**W2 말 진도 점검**: W1+W2에서 1주 이상 밀렸다면 버퍼를 이미 당겨 쓴 상태. 선택 항목부터 제외 검토.

### 흔한 함정
- 지연 측정을 대충 → W8에 정책이 이상하게 움직이는 원인
- 카메라 2대를 같은 허브에 물려 조용히 드롭
- 조명이 매일 달라져 W6~W7 데이터에 분포 이동

# W3 — Cosmos 학습 실증 및 인터페이스 확정

**주간 목표**: **학습이 얼마나 걸리는지 숫자로 안다.** 그리고 두 사람이 나중에 합칠 수 있도록 인터페이스를 문서로 고정한다.

> 이번 주가 프로젝트에서 가장 중요한 결정이 나오는 주다.
> **측정을 먼저, 최적화는 그다음.** 실측 없이 LoRA 여부를 정하지 않는다.

**주말에 있어야 할 것**
- **스텝당 학습 시간 실측치 + 총 소요 역산**
- 풀 FT vs LoRA 결정
- 데이터 규모 확정 (150 or 100)
- **로깅 스키마 문서** (A 주도)
- **관측/액션 dict 포맷 문서 + 가짜 데이터 샘플** (B 주도)

### B 작업 — Cosmos 학습 실증 (최우선)

**1단계: 풀 파인튜닝으로 먼저 (구현 불필요)**
- [ ] **4장 윈도우 확보** (몇 시간이면 충분)
- [ ] Mirobot 임베디먼트 config 초안 (액션 차원, 데이터 경로)
- [ ] 더미 또는 LIBERO 소량 데이터로 학습 스텝 100회 통과
- [ ] **VRAM 사용량 실측**
- [ ] **스텝당 소요 시간 실측**
- [ ] → 150 에피소드 학습에 필요한 총 시간 역산

**판정**

| 역산 결과 | 조치 |
|---|---|
| 4장 × 2일 이하 | **풀 파인튜닝 확정. LoRA 불필요** |
| 4장 × 2~5일 | 4장 확보 협의 vs LoRA 구현 비교 후 결정 |
| 5일 초과, 또는 4장 확보 불가 | **LoRA 구현으로 전환** |

**2단계: LoRA 구현 (위 판정에서 필요할 때만)**
- [ ] cosmos-policy 모델 구조 덤프 → 레이어 이름 목록 확보
- [ ] NVIDIA Cosmos-Predict2.5 LoRA 가이드의 target_modules 참고
- [ ] peft LoraConfig로 백본 DiT 래핑
- [ ] **액션·value 헤드는 LoRA 제외, 전체 학습**
      (Mirobot은 새 임베디먼트라 액션 차원·스케일이 기존 체크포인트와 완전히 달라, 헤드는 새로 배워야 함)
- [ ] 학습 가능 파라미터 수 출력 → 전체 대비 비율 확인
- [ ] 어댑터 저장 → 로드 → 출력 일치 확인

| 소요 | 판정 |
|---|---|
| 2~3일 | 순조로움. 계획대로 |
| 1주 | 허용 범위. 다른 작업 일정 조정 |
| 1주 초과 | **풀 파인튜닝 + 4장 확보로 되돌림** |

**3단계: 공유 서버 대응 (필수)**
- [ ] **체크포인트 저장 주기 설정 (30분~1시간)**
- [ ] **재개 스크립트 테스트** — 일부러 중단시키고 이어서 돌려볼 것
      ← 공유 서버에서 장시간 잡은 반드시 한 번은 끊긴다

### B 작업 — 백업 트랙
- [ ] 관측/액션 dict 포맷 정의 + 가짜 데이터 생성 → A 전달
- [ ] Phi-3.5-vision 로드, 이미지 2장 + 텍스트 forward 확인
- [ ] Phi VRAM·추론 지연 실측
- [ ] 액션 expert 골격 (**단순 회귀 L1 + 액션 청킹**, flow matching 아님)
- [ ] 더미 데이터 forward-backward 1스텝 통과

### A 작업

**로깅 스키마 확정 (A 주도)**
- [ ] 관절각 6개 — **명령값**
- [ ] 관절각 6개 — **실측값**
- [ ] EE pose 6자유도
- [ ] 그리퍼 상태
- [ ] 타임스탬프 — **스트림별로 각각**
- [ ] 카메라 프레임 (고정 / 손목, 원본 해상도)
- [ ] 태스크 지시문 (문자열)
- [ ] 에피소드 메타 (물체 배치, 대상 색, 성공 여부)

> ⚠️ 필드 하나가 빠지면 재수집 외에 복구 불가. 이번 주에 확정.

**액션 표현 결정**
- [ ] W2 관절각 로그 분석

| W2 결과 | 결정 |
|---|---|
| EE 명령 시 관절각 연속, 특이점 없음 | **EE 4차원** (x, y, z, 그리퍼) |

로깅은 **양쪽 모두** 기록하므로 학습 시점에 변경 가능.

**기타**
- [ ] 탈조 감지 방법 검토 (엔코더 없음 → 시각 기반 또는 주기적 호밍 검증)
- [ ] B가 만든 포맷 리뷰

### 이번 주 결정 사항
- [ ] 학습 방식: 풀 FT / LoRA
- [ ] 학습 소요 시간: ___ 일
- [ ] 데이터 규모: 150 / 100
- [ ] 액션 표현: EE 4차원 / 관절 7차원
- [ ] Phi 변형: Phi-3.5-vision / Phi-4-multimodal

### 흔한 함정
- 실측 전에 LoRA부터 구현 → 필요 없었을 수도 있는 2~3일 소모
- 포맷을 말로만 합의 → W6에 어긋남
- 재개 테스트를 안 함 → W8에 학습이 끊겨 처음부터
- 액션 expert를 flow matching으로 시작 → 학습 실패 시 원인 후보 증가

# W4 — 데이터 생성 인프라

**주간 목표**: 사람 손 없이 에피소드를 자동 생성하는 파이프라인을 완성한다.

**주말에 있어야 할 것**
- 스크립트 궤적 생성기 (좌표 입력 → 궤적 출력)
- 리셋 지그 + 물체 세트
- LeRobot 변환기 + rsync 자동 전송

### A 작업

**물리 셋업**

# W13 — 지표 산출 및 재시도 실험

**주간 목표**: 감지 성능을 수치화하고, 여유가 있으면 "감지해서 고쳤다"까지 실증한다.

### B 작업 — 필수: 오프라인 지표
- [ ] W12 롤아웃 로그로 **AUROC** 계산
- [ ] **검출 지연** 계산: 실제 실패 시작 프레임 대비 몇 스텝 먼저 감지
- [ ] **FPR 5%에서의 검출률**, 임계값 결정
- [ ] 신호 A vs B vs 조합 비교표

### A 작업 — stretch: 온라인 재시도
- [ ] 임계값 초과 시 롤아웃 중단 → 홈 복귀 → 재시도 로직 구현
- [ ] 재시도 최대 횟수 설정 (2회 정도), 재시도 전 씬 상태 확인 로직
- [ ] 태스크당 20회 롤아웃
- [ ] **성공률 비교: detector 없음 X% → 있음 Y%**

> **stretch 판단**: W13 시작 시점에 여유가 없으면 온라인 재시도를 포기하고 오프라인 지표와 문서화에 집중한다. 오프라인 AUROC + 검출 지연만으로도 권장 목표는 성립한다.

### 핵심 결과물
> "실패를 감지해 조기 중단하고 재시도했을 때, 성공률이 X%에서 Y%로 개선되었다."

### 흔한 함정
- 검출 지연을 안 재고 AUROC만 봄 → 실패 이후에 감지하는 detector도 AUROC는 높게 나옴
- 재시도 로직이 실패 상태에서 시작해 계속 실패 → 재시도 전 씬 상태 확인 필요
