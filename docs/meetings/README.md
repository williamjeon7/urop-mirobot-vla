# 주간 미팅 기록

> **기록** · 확인 2026-11-07
> 미팅 기록 작성 규칙과 양식. 문서 전반 규칙은 `../README.md` 참조.

이 프로젝트는 계획서대로 굴러가지 않는다. 방향은 **매주 연구미팅에서 교수님이** 알려 주시고, 그 주의 action plan 은 석환·민수가 짠다.
그래서 "이렇게 할 예정"이 아니라 **"이렇게 하기로 했다"** 를 남기는 곳이 여기다.

- `../plan/UROP_프로젝트_계획.md` — 설계 근거
- `../plan/운영기준.md` — 일정과 무관한 기준 (게이트, 루브릭, 함정)
- **여기** — 실제로 정해진 것. 셋이 어긋나면 이 폴더가 최신이다.

## 규칙

- 파일 하나 = 미팅 하나. 이름은 **`YYYY-MM-DD.md`** (미팅 날짜). 보고 메일·회신 같은 첨부가 있으면 날짜 폴더에 같이 둔다 (예: `2026-09-28/`).
- 미팅 **당일에** 적는다. 다음 주에 적으면 이미 왜곡되어 있다.
- 교수님 의견을 **들은 대로** 적는다. 해석과 추측은 구분해서 표시한다.
- 교수님 의견과 그 주의 **팀 action plan** 을 적는다. 할 일마다 담당을 적는다 (석환, 민수).

## 기록 양식

새 파일을 만들 때 아래를 복사한다.

```markdown
# YYYY-MM-DD 미팅

> **기록** · 미팅 YYYY-MM-DD
> 이 미팅에서 정해진 것 한 줄.

## 보고한 것
- (미팅에서 보고한 것)

## 교수님 의견
- (들은 대로. 해석은 *해석* 으로 표시)

## 확정된 결정
| 항목 | 결정 | 근거 |
|---|---|---|
|  |  |  |

## 다음 미팅까지 — action plan
### 1. (할 일)
담당: (석환 / 민수 / 공동)
- [ ]

## 다음 미팅에 가져갈 질문
-
```

- 내용이 없는 절은 뺀다. 남은 절의 순서는 바꾸지 않는다
- 담당은 이름으로 적는다 (석환, 민수)
- 11/07 이전 기록은 이 양식으로 형식만 정리했다. 머리말의 "형식 정리" 날짜가 그 표시이고, 내용은 원래 그대로다. 원문을 그대로 옮긴 첨부(보고 메일·회신)는 형식도 그대로 두었다

## 조사 결과는 여기 적지 않는다

미팅 파일에는 **미팅에서 나온 것만** 적는다. 주중에 알아낸 기술적 내용은 성격에 맞는
문서로 보낸다.

| 알아낸 것 | 갈 곳 |
|---|---|
| 그 주 조사·실험으로 나온 것 | `../W<주차>/<주제>.md` (예: `../W2/W2_진행사항.md`) |
| 계속 찾아보게 될 절차 | `../SETUP_LINUX.md`, `../VENDORED.md`, `../MODELS.md` |
| 게이트·루브릭·함정처럼 판단 기준이 되는 것 | `../plan/운영기준.md` |

이유는 두 가지다.

1. **날짜 문서에 넣으면 다시 못 찾는다.** 두 달 뒤에 "LIBERO proprio 가 뭐였지" 를
   날짜 폴더에서 뒤지지 않는다.
2. **의견과 발견이 섞인다.** 미팅 파일에 주중 메모를 덧붙이면, 나중에 무엇이 교수님
   의견이었고 무엇이 내가 알아낸 것인지 구분이 안 된다.
