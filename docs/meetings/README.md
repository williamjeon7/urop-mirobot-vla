# 주간 미팅 기록

이 프로젝트는 계획서대로 굴러가지 않는다. 방향은 **매주 연구미팅에서 교수님이** 알려 주시고, 그 주의 action plan 은 석환·민수가 짠다.
그래서 "이렇게 할 예정"이 아니라 **"이렇게 하기로 했다"** 를 남기는 곳이 여기다.

- `../plan/UROP_프로젝트_계획.md` — 설계 근거
- `../plan/운영기준.md` — 일정과 무관한 기준 (게이트, 루브릭, 함정)
- **여기** — 실제로 정해진 것. 셋이 어긋나면 이 폴더가 최신이다.

## 규칙

- 파일 하나 = 미팅 하나. 이름은 **`YYYY-MM-DD.md`** (미팅 날짜).
- 미팅 **당일에** 적는다. 다음 주에 적으면 이미 왜곡되어 있다.
- 교수님 의견을 **들은 대로** 적는다. 해석과 추측은 구분해서 표시한다.
- 두 사람이 **각자 들은 의견을 각자 적는다.** 한 명이 몰아서 정리하지 않는다.

## 담당 구분

`../plan/UROP_프로젝트_계획.md` §10 기준.

| | 담당자 | 성격 |
|---|---|---|
| **A** | (이름) | 로봇 앞에 물리적으로 있어야 하는 일 — 조립, 카메라, 수집, 롤아웃 |
| **B** | (이름) | 서버에서 할 수 있는 일 — 환경 구축, 모델, 학습, 분석 |

고정 배정이 아니다. 주차별 부하가 균등하지 않으므로 그때그때 조정한다.

## ⚠️ 엇갈린 의견을 반드시 적을 것

교수님이 A 와 B 에게 조금씩 다른 이야기를 하는 경우가 있다. **그게 이 기록을 남기는
가장 큰 이유다.** 서로 다른 전제로 몇 주를 진행하면 통합 시점에 드러나고, 그때는
되돌리기 어렵다. 계획서 §10 이 "최대 실패 모드"로 지목한 것이 이것이다.

각자 적은 의견이 충돌하거나 미묘하게 다르면 `엇갈린 의견` 칸에 적고, **다음 미팅에서
직접 확인**한다. 둘이 알아서 해석해 맞추지 않는다.

## 기록 양식

새 파일을 만들 때 아래를 복사한다.

```markdown
# YYYY-MM-DD 미팅

## 공통 지침
-

## A 의견 — (이름)
-

## B 의견 — (이름)
-

## 엇갈린 의견 / 확인 필요
- (A 와 B 가 받은 내용이 다르면 여기. 없으면 "없음")

## 확정된 결정
| 항목 | 결정 | 근거 |
|---|---|---|
|  |  |  |

## 인터페이스 합의
- (관측/액션 포맷, 로깅 스키마 등 양쪽에 걸치는 것. 정해지면 common/ 에 반영)

## 다음 미팅까지
- [ ] A:
- [ ] B:

## 다음 미팅에 가져갈 질문
-

---

## 진행 메모
(주중에 알게 된 것을 여기 덧붙인다. 미팅에서 나온 말과 구분하기 위해 분리)
```
