## 보고한 것

## 교수님 의견

- 시뮬레이션 데이터를 사용하기 힘들면, 일단 **Mirobot 데이터만으로 파인튜닝**을 진행해 보는 것이 우선이다
- 시뮬레이션 데이터를 쓰는 이유는 모든 데이터를 직접 수집하기 힘들기 때문이다. 시뮬레이션으로 그 과정을 줄이는 것은 의미가 있다
- 그 전에 선행되는 것은 **Mirobot 데이터만으로도 task 수행이 잘 되는 것**이다
- 우리의 정책이 **Cosmos Policy 가 아니어도 된다.** 어떤 정책으로라도 일단 **end-to-end** 를 진행해 보라

*해석*

- end-to-end 는 손목 영상 + 지시문 → 정책 → 실물 Mirobot 이 움직여 블록을 집는 한 바퀴 전체다. 계획서 최소 목표 "VLA 가 실기에서 end-to-end 로 동작하는 파이프라인 구축" 과 같다
- 지금 빠진 것은 정책이 아니라 정책과 실물을 잇는 **실행 루프**(아래 3-3)다. 데이터 → 학습은 Cosmos 로 한 번 끝까지 갔다. 정책 선택(Cosmos 의 무게·추론 속도)에 막혀 end-to-end 가 늦어지지 않게 하라는 뜻으로 본다. 계획서의 "Cosmos 주 정책 + Phi 백업 + ACT 진단" 중 무엇으로 먼저 돌려도 된다
- 순서가 정해졌다 — ① Mirobot 데이터만으로 task 가 되는지 → ② 시뮬 데이터로 실물 수집을 줄일 수 있는지. 시뮬 데이터를 버리라는 뜻은 아니다
- ①의 결과가 ②의 기준선이 된다. 시뮬을 섞어서 나아지는지는 Mirobot 단독 결과와 비교해야 알 수 있다
- 손목 영상 차이(ISSUES 1절)는 시뮬을 다시 섞을 때의 문제로 미뤄진다. Mirobot 단독 학습·평가에서는 녹화 때와 실행 때의 장착만 같으면 된다

### 1. Mirobot 실물 데이터 — 세 색 90개 새로 녹화

- **색마다 30개, 처음부터 다시 찍는다** — 세 색 90개. 영상1–10 은 블록 위치를 기록하지 않고 찍어서 새 데이터에 넣지 않는다
- 같은 배치에서 세 색을 모두 찍는다 — 배치 30개 × 지시문 셋. 장면만 보고 색을 맞히는 지름길을 막는다 (제안)
- 녹화마다 세 블록 좌표를 자로 재서 `layout.json` 에 적고, 위에서 찍은 사진을 함께 남긴다. 원점·축을 먼저 정해 모든 녹화에 같은 기준으로 잰다
- `?` 응답 원문(관절 각도·`Pump PWM`)을 저장한다 ([../W9/ISSUES.md](../W9/ISSUES.md) 4절)
- D405 장착·카메라 설정·색 보정은 녹화 내내 그대로 두고, 실물 평가 때도 같은 장착으로 한다
- 평가에 쓸 배치는 녹화에 쓰지 않은 것으로 따로 정해 둔다

참고: 10/29 에 10개를 16분에 찍었다 (한 개 약 1.7분). 90개면 촬영만 약 2.5시간이고, 블록 좌표 재는 시간이 더해진다.

목적: Mirobot 데이터만으로 세 색 지시를 학습할 실물 데이터를 만든다.

### 2. Mirobot 단독 파인튜닝

- **세 색 90개가 모이면 한 번에 학습한다.** 파랑만으로 먼저 돌리지 않는다
- 정책은 Cosmos Policy 가 아니어도 된다 (교수님). 첫 end-to-end 는 **세 색 90개로 학습한 Cosmos** 로 한다 — 녹화·학습이 끝난 뒤가 된다
- 데이터 형식은 지금 그대로 — 손목 영상 + Panda 형식 proprio·action. 시뮬 Panda 는 action 계산에만 쓴다. 나중에 시뮬 데이터와 다시 섞을 수 있게 (임의 판단)
- step 수는 데이터가 모이면 정한다. 1차 Mirobot 10개가 한 개 평균 약 440칸이라 90개면 약 4만 칸인데, 1차 설정 2000 step 은 32,000 샘플이라 데이터를 한 바퀴도 다 못 본다. GPU 2개로 2000 step 에 약 3시간 20분 ([../W9/FINETUNE.md](../W9/FINETUNE.md) 4·5절)

목적: 시뮬 데이터 없이 Mirobot 데이터만으로 task 가 되는지 확인한다.

### 3. 평가 — 오프라인, 실물 실행

학습한 정책을 돌려 볼 도구가 아직 없다 ([../W9/FINETUNE.md](../W9/FINETUNE.md) 7절). 녹화·학습을 기다리는 동안 만든다.

- 3-1. 오프라인 — 학습에 쓰지 않은 녹화로 예측 action 과 기록 action 을 비교한다. 로봇 없이 서버에서. 기존 영상1–10 은 새 학습에 안 들어가니 여기에 쓸 수 있다 (파랑만, 제안)
- 3-2. action → Mirobot 명령 환산 — 학습 action 은 시뮬 Panda 기준이다. 기록된 action 을 환산 규칙으로 되돌려 실물 궤적과 맞는지 먼저 본다. 로봇 없이
- 3-3. 실물 실행 루프 — D405 프레임(학습과 같은 색 보정·자르기) + 로봇 상태 → 서버 정책 → action 묶음 → Mirobot 명령, 반복. 정책 한 번 추론 시간을 잰다. 처음엔 명령만 출력해 확인하고, 그다음 저속·작업 공간 제한으로 움직인다.
  **정책을 바꿔 끼울 수 있게 만든다** — 정책 쪽은 "손목 영상·proprio·지시문 → action 묶음" 한 가지 모양으로 맞춰, 어떤 정책이든 같은 루프·같은 평가를 쓴다.
  세 색 체크포인트가 나오기 전에는 1차 혼합 체크포인트(11/02, 구조가 같다)로 **추론 시간과 명령 출력만** 확인한다 — 로봇은 움직이지 않는다. Cosmos 가 너무 느린지를 미리 알 수 있다 (제안)
- 3-4. 실물 평가 — 녹화에 안 쓴 배치에서 정해진 횟수만큼. 성공률(집어 들었나)과 언어 준수율(지시한 색 쪽으로 손을 뻗었나 — 계획서 최소 목표 60%, 무작위 33%)

목적: "Mirobot 데이터만으로 task 수행이 잘 되는가" 에 숫자로 답한다.

## 교수님 추가 의견 — 프로젝트 이후 방향 (이번 주 할 일 아님)

- Panda 기반 학습 모델(Cosmos Policy, LIBERO, π0, OpenVLA)과, Panda 로 학습되지 않은 다른 VLM 에서 from scratch 로 학습한 것을 비교하는 것이 의미가 있을 것이다
- 이번 주에 하라는 것은 아니다. 프로젝트가 끝나고 더 나아간다면 이 방향으로 알아볼 수 있다

*해석*

**한 줄로** — Panda 로 로봇 조작을 미리 배운 모델에서 출발하는 게, 로봇을 모르는 VLM 에서 출발해 Mirobot 데이터만으로 배우는 것보다 정말 나은가.

| | Panda 를 배운 모델 | Panda 를 안 배운 VLM |
|---|---|---|
| 예 | Cosmos Policy(LIBERO 체크포인트), OpenVLA, π0 | Phi-3.5-vision, PaliGemma 같은 일반 VLM |
| 이미 아는 것 | 그림, 문장, **로봇 팔 움직이는 법**(Panda 기준) | 그림, 문장뿐 |
| Mirobot 학습 | Panda 경험을 Mirobot 에 맞게 고친다 | 로봇 동작을 **처음부터** 배운다 |

- **말 풀이** — "LIBERO" 는 모델이 아니라 Panda 시뮬 벤치마크라서 "LIBERO 로 학습한 체크포인트" 로 본다. "from scratch" 는 VLM 전체를 무작위에서 시작하는 게 아니라(실물 90개로는 불가능) **VLM 의 그림·문장 지식은 쓰고 로봇 동작만 처음부터** 배운다는 뜻으로 본다
- **왜 의미가 있나** — 우리는 "Panda 를 배운 모델이 Mirobot 에도 도움이 된다" 고 가정하고 출발했지만([../W5/CHECKPOINT.md](../W5/CHECKPOINT.md)) 확인한 적은 없다. Panda 와 Mirobot 은 카메라 시점·팔·집게가 달라서 Panda 경험이 도움일 수도, 방해일 수도 있다
- **결과가 어느 쪽이든 답이 된다**
  - Panda 쪽이 크게 낫다 → 한 로봇에서 배운 것이 다른 로봇에도 옮겨 간다
  - 비슷하다 → 작은 로봇에서는 VLM 의 그림·문장 지식이 핵심이다
  - VLM 쪽이 낫다 → Panda 습관이 오히려 방해한다
- **비교할 때** — 같은 Mirobot 데이터, 같은 실물 평가. 모델 크기가 달라서(Cosmos 2B, π0 약 3B, OpenVLA 7B) **바탕이 같은 것끼리** 짝지어야 Panda 학습의 효과만 볼 수 있다 — π0 vs PaliGemma, OpenVLA vs 그 바탕 VLM, Cosmos Policy LIBERO vs Cosmos-Predict2
- **이미 한 것과의 연결**
  - W5 출발 가중치 비교 — Panda 를 배운 `Cosmos-Policy-LIBERO` vs 로봇을 본 적 없는 영상 모델 `Video2World`. Cosmos 안에서 같은 모양의 비교를 하고 앞의 것을 골랐다 ([../W5/CHECKPOINT.md](../W5/CHECKPOINT.md))
  - 계획서 **Phi 백업 트랙**(로봇 데이터 없는 Phi-3.5-vision + action 출력부)이 "Panda 를 안 배운 VLM" 쪽이다 ([../plan/UROP_프로젝트_계획.md](../plan/UROP_프로젝트_계획.md))
  - 이번 주 Mirobot 90개와 평가 도구가 이 비교의 공통 데이터·평가가 된다 — 모델만 바꿔 끼우면 된다
- **교수님 뜻과 다를 수 있는 곳** — "from scratch" 의 범위, 그리고 OpenVLA·π0 을 "Panda 기반" 이라 하신 뜻 (둘 다 Panda 만이 아니라 여러 로봇 데이터로 학습했고 Panda 가 많이 들어 있다)
